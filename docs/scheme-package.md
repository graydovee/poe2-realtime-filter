# 方案包

分享码只带规则。方案包把一个或多个方案连同它们用到的基础过滤器和自定义音效打成一个 ZIP，接收方导入后可以直接编辑和安装。作者更新了包之后，导入过的人再导入一次，方案和基础过滤器都按 ID 同步到新版本。

| 桌面命令 | 行为 |
| --- | --- |
| `scheme_export_package(ids, title?)` | 给包里用到的基础过滤器找到或新建表记录，流式写出 ZIP。用户取消另存为时，登记照样保留，下次导出沿用同一个 ID。 |
| `pick_scheme_package()` | 弹系统打开框。选中后读包并全量校验，返回导入计划和该服务器的赛季目录；取消返回 `null`。 |
| `scheme_import_package(path, decisions)` | 重新读包、重算计划后应用。先写表，再一次性写方案库。 |

## ID

| 对象 | ID 从哪来 | 用途 |
| --- | --- | --- |
| 方案 | `Scheme.id`（UUID），随包传播 | 判断是不是同一个方案；导入时沿用这个 ID |
| 规则 | 方案里的规则 ID，随包保留 | 导入后规则 ID 不变，编辑、撤销和报告据此标识规则 |
| 基础过滤器 | 首次登记时随机生成，32 位十六进制 | 区分每一份基础过滤器，随包传播 |

## 基础过滤器表

文件是 `data\base-filters.json`，和 `library.json` 并列。进出过方案包的基础过滤器都登记在这里，只增不删。

| 字段 | 含义 |
| --- | --- |
| `id` | 随机生成的 ID |
| `name` | 本名。所有界面显示它 |
| `base` | 本机怎么提供这份过滤器：游戏订阅、下载缓存、本地文件的描述，或安装目录里的副本 |
| `origin` | 最初来源 |
| `content` | 副本的文件集合散列，只用来判断内容有没有变 |
| `registeredAt` | 登记时间，Unix 秒 |

导出时按这个顺序找记录：

1. 描述完全相同。
2. 同一个订阅的同一个条目，或同一下载来源的同一个文件。下载型被托盘升级了版本、游戏目录换了位置，ID 都不变。
3. 都没有就新建记录。

多个方案共用一份时只有一条记录，所以作者反复导出时 ID 不变。本地文件型只在路径完全相同时才视为同一份：两个目录下的同名文件可能是不同的过滤器。

## 包格式

ZIP，DEFLATE 压缩。单个方案导出时文件名是「方案名 方案包.zip」；多个方案时用包名称，没填则叫「方案包.zip」。

| 条目 | 内容 |
| --- | --- |
| `manifest.json` | 清单，带缩进的 JSON |
| `bases/<基础过滤器 ID>/<相对路径>` | 入口文件、`Import` 依赖、被引用的音效 |
| `sounds/<sha256>` | 自定义音效，按内容去重 |

```json
{
  "format": 1,
  "title": "开荒到终局",
  "appVersion": "0.5.15",
  "bases": [
    {
      "id": "3f2a91bea8b3c1d40e7f6a5b4c3d2e1f",
      "name": "NeverSink-6uberplu-poe2",
      "origin": { "kind": "subscribed", "source": "online" },
      "entry": "OnlineFilters/4pQrzmUJ",
      "files": [{ "path": "OnlineFilters/4pQrzmUJ", "sha256": "…" }]
    }
  ],
  "schemes": [
    {
      "id": "a88bba0b-a9f3-4b8e-bc92-2771304561d9",
      "name": "终极打宝-自动更新物价",
      "description": "开荒到终局的一套打法，自动跟随物价",
      "base": "3f2a91bea8b3c1d40e7f6a5b4c3d2e1f",
      "sounds": { "提示音.mp3": "…" },
      "profile": { "…": "完整方案，保留规则 ID" }
    }
  ]
}
```

- `title`、`appVersion` 可选，只作说明。
- `description` 是方案的描述，为空时省略。
- `profile` 是经方案校验和迁移后的完整内容，保留规则 ID；`baseFilter` 换成名称提示 `baseFilterHint`。
- 方案没有基础过滤器内容时省略 `base`，只留名称提示。
- `origin` 只用于导入时匹配和显示，客户端只读取本机来源的路径。
- `format` 不是 1 时提示升级客户端；其余字段严格解析。

基础过滤器的根目录按来源取：本地文件是入口文件所在目录，订阅是游戏目录，下载是版本目录。依赖或音效在根目录之外、或者引用了本机绝对路径的音效时，导出报错。

## 大小

导出不设数量和大小上限，包里的文件沿用客户端已有的读写限制。

导出把 ZIP 直接流式写进目标目录下的临时文件再改名；导入从磁盘流式读取，边解压边算 sha256。

导入时每趟解压累计超过 4 GiB 就中止，用来挡住损坏或恶意的文件。

## 导入时的处理

### 方案

按方案 ID 判断。

| 情况 | 结果 |
| --- | --- |
| 本机没有这个 ID | 新导入，沿用包里的 ID。同服务器有别的方案重名时，默认改用一个空闲的「X 副本」，可以再改 |
| 本机有这个 ID，内容相同 | 已是最新，跳过，不询问 |
| 本机有这个 ID，内容不同 | 更新：同步名称、描述、方案设置、规则、基础过滤器和音效。默认选「更新」，可以改为跳过或另存为副本 |
| 同一个 ID 在另一个服务器 | 只能跳过或另存为副本 |

更新时本机的自动刷新开关和安装状态保持不变。已安装的方案改名时，游戏里的过滤器文件跟着改名，并标记「方案已更新，请重新生成」。包里的名称已被本机另一个方案占用时不能更新。

「内容相同」比较名称、描述、去掉基础过滤器引用后的方案内容、音效映射和基础过滤器内容散列。

### 基础过滤器

先查表，再在本机找。

| 情况 | 结果 |
| --- | --- |
| 表里有这个 ID，指向本机的来源且能读取 | 直接用，不询问 |
| 表里有这个 ID，指向副本，内容相同 | 直接用，不写文件 |
| 表里有这个 ID，指向副本，内容不同 | 默认「更新副本」，可以改为保留本机的 |
| 表里没有这个 ID，本机有内容相同的 | 直接用那份，不询问 |
| 表里没有这个 ID，本机有同名但内容不同的订阅、下载或副本 | 默认「用本机的」，可以改为用包里的 |
| 都没有 | 导入包内副本 |

无论哪种结果，都把这个 ID 登记进表，指向最终用的那一份，下次导入同一个 ID 时直接沿用。记录指向的来源读不到时（退订、文件被删），当作没有这个 ID 重新找。

### 副本

- 只写进安装目录 `data\base-filters\imported\<ID>\`。
- 基础过滤器来源类型 `imported` 指向它：`{ "kind": "imported", "id": "…", "entry": "…", "name": "本名" }`。
- 副本是静态的，内容保持导入时的样子。编辑器的「选择已有过滤器」把它们单独列在「方案包导入」一组，显示本名；两份同名时用登记日期区分。
- 导入分享码时，游戏目录里没有唯一同名项的话，接着在这些副本里找。

## 用户的选择

`scheme_import_package` 的 `decisions`，下标都是包内下标：

```json
{
  "league": "Forbidden Rites",
  "names": { "1": "另起的名称" },
  "schemeSkips": [3],
  "schemeCopies": [5],
  "baseKeeps": [0],
  "baseCopies": [1]
}
```

- `league`：包里的赛季已不存在时，这些方案改用的赛季。
- `names`：新方案和副本另起的名称。
- `schemeSkips`、`schemeCopies`：不更新的方案、要另存为副本的方案。
- `baseKeeps`、`baseCopies`：保留本机副本的基础过滤器、改用包内副本的基础过滤器。
