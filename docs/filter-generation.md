# 过滤器生成与更新

Tauri 客户端使用静态 Next.js 页面呈现编辑器。Rust 管理方案、基础过滤器、行情缓存和输出文件，通过内嵌 QuickJS 调用 TypeScript 生成器。预览、安装、下载 ZIP 和托盘刷新使用同一套规则。

## 基础过滤器

制作页可以选择游戏内过滤器、本地文件或下载来源。游戏内列表读取普通 `.filter` 和游戏缓存的订阅过滤器，默认隐藏订阅项。清除基础过滤器后按自定义规则生成，未匹配物品使用游戏默认显示。下载菜单按来源选择，NeverSink 使用官方 GitHub Release，过滤器和音效按版本缓存到安装目录的 `data/base-filters`。

本地方案保存所选文件的路径，生成时读取当前文件。使用下载来源时，方案引用所选版本中的文件。更换版本时，打开制作页重新选择。

## 行情与刷新

`worker/market-adapter.mjs` 优先使用 poe.ninja 交易所的 Most Popular 单件价格，有效换算额为 `1 / maxVolumeRate`。缺少有效的 Most Popular 报价时使用 `primaryValue`。生成器使用 Currency 分类的统一汇率，将价格和规则阈值换算为崇高石。

客户端按赛季缓存行情和响应验证头，一轮刷新内，同赛季方案共用行情结果。已安装且开启自动刷新的方案会参与托盘刷新。行情请求失败时，游戏继续使用上次生成的过滤器。

## 规则匹配与特效

优先级依次为跳过名单、列表中第一条命中的规则、基础过滤器。没有基础过滤器时，跳过名单暂存，未命中规则的物品使用游戏默认显示。

| 启用的条件 | 命中范围 |
| --- | --- |
| 物品 | 已选物品 |
| 价格 | 报价落在 `[min, max)` 的物品 |
| 物品与价格 | 已选且报价落在区间内的物品 |

每个条件都有独立开关。关闭条件时保留已编辑的值。启用规则时至少提供一组可用于匹配的条件。跟随市价的规则用崇高石、混沌石、剥离石和神圣石作为价格锚点，最高档向上开放。锚点缺价时，预览报告会标出暂停匹配的价格档。

`lib/filter-engine.ts` 按编辑顺序匹配每条规则，生成 `Show` 或 `Hide` 以及该规则设置的显示动作。开了「跟随基础过滤器」的默认规则，通过 `lib/baseline-effects.ts` 读取对应通货的样式。样式解析考虑基础规则顺序、匹配条件和 `Continue`。无法确定样式时，使用游戏默认显示样式，并在预览中说明原因。手工修改特效会切换为规则自己的样式。

## 生成与安装

过滤器文件由方案注释、自定义规则和末尾规则组成。末尾使用选定的基础过滤器，纯自定义方案使用默认显示规则。客户端在生成时处理本地 `Import` 以及自定义音效依赖。音效按内容散列命名，ZIP 使用与安装相同的文件和目录结构。

预览报告显示规则命中、缺少报价、基础样式和安全检查结果。检查会标记被隐藏的高价值物品，以及跳过名单中被自定义规则隐藏的物品。通过行情、资源和安全检查后，客户端将生成结果安装为 `<方案名>.filter`。内容与已安装文件一致时继续使用现有文件。无法生成时，方案页显示原因，游戏继续使用上次的文件。

## 分享码

复制分享码会生成 `POE2F1.<协议头>.<载荷>`，协议头与载荷使用无填充 Base64URL。`src-tauri/src/share_code.rs` 比较两种 Brotli 压缩结果的完整码长，从 `poe2` 规则编码与 `br` 方案 JSON 中选择更短的一种，同长时优先 `poe2`。协议头以 `alg` 标识算法，以 `p` 标识参数档位。`poe2` 档位固定对应规则布局和物品编号表。

导入时校验载荷完整性与方案格式，然后创建本地方案。分享码携带规则、方案设置、基础过滤器名称提示和音效文件名。导入时根据名称在游戏目录中查找唯一匹配的基础过滤器。待处理的引用会显示在方案列表，用户可在编辑页选择或清除，并按提示补齐音效。
