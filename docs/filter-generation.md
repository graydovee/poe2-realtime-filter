# 过滤器生成与更新

Tauri 客户端使用静态 Next.js 页面呈现编辑器。Rust 管理方案、基础过滤器、行情缓存和输出文件，通过内嵌 QuickJS 调用 TypeScript 生成器。预览、安装、下载 ZIP 和托盘刷新使用同一套规则。

## 基础过滤器

编辑器里可以选择已有的过滤器、本地文件或下载来源。已有的过滤器列表读取游戏目录里的普通 `.filter`、游戏缓存的订阅过滤器，以及方案包导入的副本（单独成组，显示本名），默认隐藏订阅项。清除基础过滤器后按自定义规则生成，未匹配物品使用游戏默认显示。下载菜单按来源选择，NeverSink 使用官方 GitHub Release，过滤器和音效按版本缓存到安装目录的 `data/base-filters`。

本地方案保存所选文件的路径，生成时读取当前文件。使用下载来源时，方案引用所选版本中的文件。托盘检查到来源发布了新版本后，把方案切换到新版里的同名过滤器；已安装且开启自动刷新的方案随之重新生成。

## 行情与刷新

`worker/market-adapter.mjs` 优先使用 poe.ninja 交易所的 Most Popular 单件价格，有效换算额为 `1 / maxVolumeRate`。缺少有效的 Most Popular 报价时使用 `primaryValue`。生成器使用 Currency 分类的统一汇率，将价格和规则阈值换算为崇高石。

未切割宝石在 poe.ninja 上按等级逐个报价（`Uncut Skill Gem (Level N)` 等），所以目录里每个等级是一件独立物品，各有各的价格。腾讯服的行情源没有宝石报价，这些物品按无报价处理，只受物品条件约束。

剥离石没有固定汇率。规则价格区间以它为单位时，按它自己的当日报价换算；区间里用到剥离石而当时没有报价，就无法换算，客户端拒绝生成并说明原因。选中的个别物品没有报价不算错误，它们只是不被这条规则命中。

腾讯服使用 poecurrency.top 的 POE2 赛季和汇总报价，赛季 ID 与显示名沿用接口原值。报价优先取有效买一价，其次取卖一价，统一折算为崇高石。

客户端按服务器和赛季缓存行情和响应验证头。一轮刷新内，同服同赛季方案共用行情结果。已安装且开启自动刷新的方案会参与托盘刷新。行情请求失败时，游戏继续使用上次生成的过滤器。

## 规则匹配与特效

优先级依次为跳过物品、列表中第一条命中的规则、基础过滤器。没有基础过滤器时，跳过物品暂存，未命中规则的物品使用游戏默认显示。

选择物品支持中英文搜索、分类与搜索结果批量选择。物品目录是 0.5.5 版本物品列表：收哪些物品和传奇、传奇挂在哪件基底上、传奇的译名，都以 `data/item-list.json` 为准，`npm run validate:data` 逐件核对目录和它完全一致。上游数据由 poe2-filter-data skill 取来，写成成品文件放在 `data/` 下；生成目录的脚本只读这些成品文件和客户端的物品表（`BaseItemTypes`，提供其余物品的三语名称、物品类别和掉落等级），不联网。可堆叠名单和图标取自 `data/item-details.json`。图标从上游按需加载：PoE2 Wiki 的图片文件，或另一家图床上的完整地址；分类的图标记在分类树的 `icon` 里，也是图床上的地址；搜索目录随客户端提供。

装备基底清单照物品列表，由 `node scripts/sync-client-items.mjs <客户端版本目录>` 写进目录。只给传奇挂基底、物品列表里没有单列的几件（华服装束、永恒珠宝、戒指、永霜法杖、饕餮法杖）也在目录里，只以传奇的身份出现。

选择器的分类树在 `data/item-categories.json`，顶层依次是通货、传奇、玩法、终局、符文、精髓、技能、装备、其他。每件物品归到哪个叶子由 `scripts/lib/item-classes.mjs` 的规则按它的客户端记录算出来：物品类别编号、标签和编号。规则 reproduce 物品列表的归属，`data/item-category-reference.json` 存着列表里每件物品所在的叶子和它的客户端记录，`tests/item-categories.test.mjs` 逐件核对。列表里标成「不存在」的物品按名单归在「其他 › 不存在」。

装备基底按武器、防具、饰品、副手分在「装备」下，防具再按属性需求（力、敏、智及其组合）拆开，盾牌分三种。出了传奇的基底在「传奇」下按同样的类型各有一个条目，名字是传奇的名字，第二行写着基底的名字；药瓶、咒符、石板和圣物上的传奇也在这里。「装备」只收物品列表里单列、而且有不止出传奇的记录的基底；只出传奇的基底（客户端表里编号带 `Unique`，例如符文之叉，它是「符文猎手的呼唤」的基底）只出现在「传奇」里。这项判定记在 `data/item-drop-metadata.json` 的 `dropEnabled` 里，由 `sync-client-items.mjs` 写入，`npm run validate:data` 检查每件装备基底都有记录。同名基底只要有一条不止出传奇的记录，普通变体就保留。

读取方案时，物品目录里曾经有过、后来移除的物品从规则和跳过物品里去掉。完全不认识的物品 ID 仍然报「规则物品无效」或「跳过物品无效」，例如更新版本客户端导出的方案包带了新的物品。

物品选择、单件价格和掉落条件同时启用时取交集。单件价格使用 `[min, max)` 区间。掉落条件支持堆叠数量 `StackSize`、稀有度 `Rarity`、物品等级 `ItemLevel`、孔数 `Sockets` 和未鉴定阶级 `UnidentifiedItemTier`。通货可共享堆叠阈值，也可用多条规则设置不同的数量档。同一掉落按列表顺序执行首条命中的规则。

未切割宝石（技能 1–20 级，精魂 4–20 级，辅助 1–5 级）的每个等级是目录里的一件独立物品：它们在游戏里共用一个基底，生成器写出 `BaseType` 加 `GemLevel = N` 来区分。不同等级互不覆盖，跳过物品也只排除选中的那个等级。等级属于物品本身。

换界石 16 阶各是目录里的一件物品，从 16 阶排到 1 阶，放在「终局 › 换界石」下。生成器写出 `Class == "Waystones"` 加 `WaystoneTier = N` 区分阶数；一条规则把 16 阶全选时合并成一条 `Class == "Waystones"`。旧方案里选的是代表整个类别的换界石条目，读取时换成这 16 阶，生成出来的过滤器不变。换界石没有行情，不能带价格条件。

规则把一个游戏类别的逐件物品全部选中（例如四个玩法下的全部预兆，或「装备 › 饰品 › 项链」的全部基底），并且没有启用价格条件时，生成器把这一类合并成一条 `Class` 条件，装备再带上 `Rarity < Unique`（普通基底）或 `Rarity Unique`（传奇），无需逐件写出。是否合并由生成器判断：少选一件、这一类里有物品在跳过物品里，或者规则带价格条件（整类条目没有行情）时，逐件输出。整类条件会命中游戏里该类别的所有物品，包括目录没有收录的。远征日志、任务物品在目录里没有逐件物品，在选择器里各是一件物品，选中它就是整类匹配。

哪些类别可以整类匹配记在 `lib/catalog-view.ts` 的登记表里，每个类别登记它覆盖的客户端类别编号，成员是这些类别里的逐件物品。一个类别的物品可以分在几个分类里：预兆分在四个玩法下，头盔按属性分成七种，全选才算整类。登记的条件是「这个类别确实对应这些物品」，逐条的依据写在 `tests/class-matches.test.mjs`：预兆、咒符、孕育器以内置 NeverSink 过滤器里的实际配对为准；血脉宝石、符文技能宝石、巅峰钥匙、宝库钥匙以 GGG 的过滤器更新公告为准；换界石以 NeverSink 按 `WaystoneTier` 写的条件为准，它覆盖 1–16 阶。石板、插槽物品、地图碎片和 `Stackable Currency` 不整类匹配，按逐件输出。

生成器写出的语法以 GGG 的官方文档 [About Item Filters](https://www.pathofexile.com/item-filter/about) 为准：运算符、`PlayAlertSound` 的编号和音量范围、`MinimapIcon` 的颜色和形状、`PlayEffect` 的颜色、字号范围、`Identified`、`GemLevel`、`WaystoneTier`、`UnidentifiedItemTier` 都和文档一致。游戏每次改动过滤器相关内容时，GGG 会在论坛发布当个赛季的 Item Filter Information，类别和物品的改名、删除以它为准。

每组条件使用独立开关并保存编辑值。价格区间的端点是普通的「数值 + 单位」，单位可选崇高石、混沌石、剥离石和神圣石。新方案自带的四个价格档（崇高石、混沌石、剥离石、神圣石）就是普通规则：每档「≥ 1 枚本档通货，且 < 1 枚下一档通货」，最高档不封顶，数值、单位、物品范围都能改。四档的顺序按最近几个赛季的价值排；某个赛季里相邻两档价值倒挂时（例如标准赛季的剥离石比混沌石便宜），对应区间会反过去，编辑器会提示「下限不低于上限」，调一下数值或单位即可。

`lib/filter-engine.ts` 按编辑顺序匹配每条规则，生成 `Show` 或 `Hide` 和显示动作。跟随基础特效的规则通过 `baselineEffectItemId` 指定来源物品，四条默认价格档分别以本档通货为来源。预览和生成都通过 `lib/baseline-effects.ts` 从当前基础过滤器解析样式，考虑规则顺序、匹配条件和 `Continue`。切换基础过滤器后会重新解析同一物品。无法确定时会使用游戏默认显示样式并提示原因。手动修改外观或音效后，规则使用自己的特效值。

### 对基础规则的修改

方案可以对基础过滤器里的单条规则做修改（`profile.overlays`，每项是一个 `BaseOverlay`）：改成显示或隐藏、整组替换匹配条件、替换光柱、地图图标、字号、三种颜色和音效。特效和音效逐项覆盖，没写的项沿用基础规则。

全部修改有一个总开关 `editsEnabled`，默认打开。关闭时生成器把所有修改按关闭处理，它们不写进过滤器；每处修改自己的 `enabled` 保留着，重新打开后各自按启用状态生效。

每处修改记着建立时的基础过滤器名（`baseName`）和那条规则规范化后的条件行（`conditions`），生成时靠它们在当前基础过滤器里找到对应的规则（`lib/base-overlays.ts` 的 `resolveOverlays`）：

- 方案没有基础过滤器，或当前基础过滤器的名字和 `baseName` 不同，这处修改失效。
- 名字相同时按条件行匹配，不分大小写；条件相同的几条规则一起命中。找不到条件相同的规则（更新后条件变了或规则没了），这处修改失效。改过的条件（`conditionLines`）不参与匹配。
- 失效的修改和关闭的修改（`enabled` 为 false）不写进过滤器，其余部分照常生成。启用的修改失效时，预览报告按原因提示。换回对应的基础过滤器后恢复。

生成时 `applyOverlays` 在原位置改写命中的规则（`lib/filter-blocks.ts` 按行切出规则）：显示或隐藏变了就换块首的 `Show` / `Hide`，后面的注释保留；改了条件就把块里的条件行整组换掉；写了的特效和音效替换该动作原有的行，原来没有的加在块尾。`Continue`、`DisableDropSound` 和块内注释原样保留，换行风格跟着原文件。基础过滤器其余部分一个字节都不变。引擎把改写后的基础正文作为 `baseText` 返回，Rust 处理音效时以它切分生成结果。

修改里的自定义音效和基础过滤器音效在正文里带着客户端的前缀（`@poe2rf-custom/`、`@poe2rf-baseline/`），`prepare_sounds` 按前缀分辨它们，写在基础正文里也能换成按内容散列命名的文件。方案引用的自定义音效从规则和修改里一起收集。

安全检查：修改把一条规则改成隐藏，或者改了一条本来就隐藏的规则的条件时，在改写后的正文上模拟价值不低于 1 枚神圣石的目录物品最终落到哪条规则。落进这些规则的记为隐藏高价值物品，安全检查不通过。

改过的条件只做基本的语法检查（条件名、运算符、值和引号，`conditionLineIssue`）。条件名在当前基础过滤器里没出现过时，编辑器提醒确认拼写。每个方案最多 500 处修改，每处最多 40 行条件。

界面上，规则面板的「显示基础规则」开关打开后，规则列表的下面按分节列出基础过滤器的规则，可以搜索；在当前基础过滤器上失效的修改列在最前面。改一条基础规则的任意一项就建立修改，所有改动都清掉时修改删除。「批量操作」菜单复制、粘贴整个方案的修改，粘贴时同一条基础规则的修改覆盖本方案原有的，其余追加；「还原基础规则」去掉方案里全部修改。标题栏的「基础规则修改：开 / 关」按钮是总开关（`editsEnabled`），方案有基础过滤器时一直显示；关闭时全部修改不生效，基础规则只读，「批量操作」里复制、粘贴、还原基础规则三项不显示。

### 升级物品目录

物品目录是 0.5.5 版本物品列表。上游数据由独立的 poe2-filter-data skill（https://git.graydove.cn/graydove/poe2-spider）取来，
怎么取、有哪些参数见它的说明；物品种类和物品目录的生成规则见 `scripts/lib/item-classes.mjs` 和各脚本开头的说明：

```bash
# 1. 取上游数据：物品列表和物品详情两个成品文件写进 data/；其余参数见 poe2-filter-data 的说明
node <poe2-spider>/poe2-filter-data/scripts/update-filter-data.mjs --version <游戏版本> --data <客户端数据仓库根目录>

# 2. 生成目录；不带 --apply 只报告差异
npm run catalog:update -- --client <客户端版本目录> [--apply]
```

`catalog:update` 不联网。它由物品列表和客户端表生成参考数据，按同一份列表补全装备基底、核对传奇、通货、材料、宝石和终局物品（列表里有的补上，没有的去掉），用客户端表刷新三语名字和掉落等级，按物品详情补图标和可堆叠名单，最后按客户端表给每件物品定分类、同步分享码的槽位和分类序号，并运行 `validate:data`。

物品目录跟着物品列表走。列表调整分类时，先改 `data/item-categories.json`，然后按 `tests/item-categories.test.mjs` 报出的差异调整 `scripts/lib/item-classes.mjs` 的规则，最后 `node scripts/build-catalog-groups.mjs <客户端版本目录>` 给目录重新定分类。

## 生成与安装

过滤器文件由方案注释、自定义规则和末尾规则组成。末尾使用选定的基础过滤器，纯自定义方案使用默认显示规则；被修改命中的基础规则已经原地改写。客户端在生成时处理本地 `Import` 以及自定义音效依赖。音效按内容散列命名，ZIP 使用与安装相同的文件和目录结构。

预览报告提供完整过滤器文本，显示规则命中、可确认的规则覆盖、缺少报价、基础样式和安全检查结果。检查会标记被隐藏的高价值物品，以及跳过物品中被自定义规则隐藏的物品。通过行情、资源和安全检查后，客户端将生成结果安装为 `<方案名>.filter`。内容与已安装文件一致时继续使用现有文件。无法生成时，方案库显示原因，游戏继续使用上次的文件。

### 基础过滤器兼容性检查

游戏遇到不认识的物品类别时会拒绝加载整份过滤器，所以基础过滤器也要和当前游戏版本相符。生成器在拼好的最终文本上检查所有生效的 `Class` 条件（注释行不算）：

- 用了游戏已经改名的类别（名单在 `lib/filter-engine.ts` 的 `RENAMED_ITEM_CLASSES`，目前只有 `Socketable → Augment`）时，安全检查不通过，不安装。提示里带着最终文本里的行号，和游戏报错里的行号是同一个数，例如「第 5602 行：物品类别 "Socketable" 已被游戏改名为 "Augment"」。安装时把这个原因直接告诉用户。
- 基础过滤器是 NeverSink、且文件头里的版本号比应用内置的参考版本旧时，给一条不阻断的提醒。参考版本在 `NEVERSINK_REFERENCE_VERSION`，测试保证它和仓库里的 NeverSink 文件头一致。

名单只收录有 GGG 官方依据的改名。

## 分享码

在方案的「更多 → 分享码」复制，接收方可通过「导入分享码」创建可编辑的新方案。客户端生成 `POE2F2`，也可导入 `POE2F1`。分享码携带服务器、原始赛季 ID、方案设置、规则、对基础规则的修改和跳过物品。格式与兼容性见[分享码协议](share-code.md)。

分享码通过名称引用基础过滤器和音效。导入时，客户端在游戏目录中查找唯一匹配的基础过滤器，没有时再查方案包导入的副本。待处理的引用会显示在「方案库」，可在编辑器里选择或清除。缺少的自定义音效按提示补齐。

## 方案包

方案包把方案、基础过滤器和自定义音效一起分享，保留方案 ID，同一个包再次导入时按 ID 更新。格式、基础过滤器表和导入时的处理见[方案包](scheme-package.md)。
