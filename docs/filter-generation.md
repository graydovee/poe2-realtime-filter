# 过滤器生成与更新

Tauri 客户端使用静态 Next.js 页面呈现编辑器。Rust 管理方案、基础过滤器、行情缓存和输出文件，通过内嵌 QuickJS 调用 TypeScript 生成器。预览、安装、下载 ZIP 和托盘刷新使用同一套规则。

## 基础过滤器

制作页可以选择游戏内过滤器、本地文件或下载来源。游戏内列表读取普通 `.filter` 和游戏缓存的订阅过滤器，默认隐藏订阅项。清除基础过滤器后按自定义规则生成，未匹配物品使用游戏默认显示。下载菜单按来源选择，NeverSink 使用官方 GitHub Release，过滤器和音效按版本缓存到安装目录的 `data/base-filters`。

本地方案保存所选文件的路径，生成时读取当前文件。使用下载来源时，方案引用所选版本中的文件。更换版本时，打开制作页重新选择。

## 行情与刷新

`worker/market-adapter.mjs` 优先使用 poe.ninja 交易所的 Most Popular 单件价格，有效换算额为 `1 / maxVolumeRate`。缺少有效的 Most Popular 报价时使用 `primaryValue`。生成器使用 Currency 分类的统一汇率，将价格和规则阈值换算为崇高石。

未切割宝石在 poe.ninja 上按等级逐个报价（`Uncut Skill Gem (Level N)` 等），所以目录里每个等级是一件独立物品，各有各的价格。腾讯服的行情源没有宝石报价，这些物品按无报价处理，只受物品条件约束。

剥离石没有固定汇率。规则价格区间以它为单位时，按它自己的当日报价换算；区间里用到剥离石而当时没有报价，就无法换算，客户端拒绝生成并说明原因。选中的个别物品没有报价不算错误，它们只是不被这条规则命中。

腾讯服使用 poecurrency.top 的 POE2 赛季和汇总报价，赛季 ID 与显示名沿用接口原值。报价优先取有效买一价，其次取卖一价，统一折算为崇高石。

客户端按服务器和赛季缓存行情和响应验证头。一轮刷新内，同服同赛季方案共用行情结果。已安装且开启自动刷新的方案会参与托盘刷新。行情请求失败时，游戏继续使用上次生成的过滤器。

## 规则匹配与特效

优先级依次为跳过名单、列表中第一条命中的规则、基础过滤器。没有基础过滤器时，跳过名单暂存，未命中规则的物品使用游戏默认显示。

选物支持中英文搜索、分类与搜索结果批量选择。物品图标和基底掉落等级使用 PoE2 Wiki 的物品资料。传奇装备译名使用流亡 2 编年史的多语言目录。图标从上游按需加载，分类占位图和搜索目录随客户端提供。

物品选择、单件价格和掉落条件同时启用时取交集。单件价格使用 `[min, max)` 区间。掉落条件支持堆叠数量 `StackSize`、稀有度 `Rarity`、物品等级 `ItemLevel`、孔数 `Sockets` 和未鉴定阶级 `UnidentifiedItemTier`。通货可共享堆叠阈值，也可用多条规则设置不同的数量档。同一掉落按列表顺序执行首条命中的规则。

未切割宝石（技能、精魂 1–20 级，辅助 1–5 级）的每个等级是目录里的一件独立物品：它们在游戏里共用一个基底，生成器写出 `BaseType` 加 `GemLevel = N` 来区分。不同等级互不覆盖，跳过名单也只排除选中的那个等级。等级属于物品本身，不是掉落条件。

每组条件使用独立开关并保存编辑值。价格区间的端点是普通的「数值 + 单位」，单位可选崇高石、混沌石、剥离石和神圣石。新方案自带的四档价格规则（崇高石、混沌石、剥离石、神圣石）就是普通规则：每档「≥ 1 枚本档通货，且 < 1 枚下一档通货」，最高档不封顶，数值、单位、物品范围都能改。四档的顺序按最近几个赛季的价值排；某个赛季里相邻两档价值倒挂时（例如标准赛季的剥离石比混沌石便宜），对应区间会反过去，编辑器会提示「下限不低于上限」，调一下数值或单位即可。

`lib/filter-engine.ts` 按编辑顺序匹配每条规则，生成 `Show` 或 `Hide` 以及该规则设置的显示动作。四条默认价格规则还没自定义特效时（内部的 `followBaseline` 标记），通过 `lib/baseline-effects.ts` 读取对应通货的样式，界面上把它当成当前选中的预设显示。样式解析考虑基础规则顺序、匹配条件和 `Continue`。无法确定样式时，使用游戏默认显示样式，并在预览中说明原因。换一个预设或手工修改特效后，这条规则改用自己的样式。

## 生成与安装

过滤器文件由方案注释、自定义规则和末尾规则组成。末尾使用选定的基础过滤器，纯自定义方案使用默认显示规则。客户端在生成时处理本地 `Import` 以及自定义音效依赖。音效按内容散列命名，ZIP 使用与安装相同的文件和目录结构。

预览报告提供完整过滤器文本，显示规则命中、可确认的规则覆盖、缺少报价、基础样式和安全检查结果。检查会标记被隐藏的高价值物品，以及跳过名单中被自定义规则隐藏的物品。通过行情、资源和安全检查后，客户端将生成结果安装为 `<方案名>.filter`。内容与已安装文件一致时继续使用现有文件。无法生成时，方案页显示原因，游戏继续使用上次的文件。

## 分享码

复制分享码会生成 `POE2F1.<协议头>.<载荷>`，协议头与载荷使用无填充 Base64URL。v2 方案从 `poe2` 规则编码与 `br` 方案 JSON 中选择码长更短的一种，同长时选 `poe2`。v3 方案使用 `br` 参数档位 `3`，记录掉落条件和对应开关。协议头以 `alg` 标识算法，以 `p` 标识参数档位。`poe2` 档位固定对应规则布局和物品编号表。

导入时校验载荷完整性与方案格式，然后创建本地方案。分享码携带服务器、原始赛季 ID、规则、方案设置、基础过滤器名称提示和音效文件名。导入时根据名称在游戏目录中查找唯一匹配的基础过滤器。待处理的引用会显示在方案列表，用户可在编辑页选择或清除，并按提示补齐音效。
