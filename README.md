# PoE2 Realtime Filter

面向《流放之路 2》的 Windows x64 掉落过滤器编辑器。可以按赛季行情、物品分类或指定物品设置显示规则，也可以在现有过滤器上叠加规则。客户端支持腾讯服和国际服，可定时读取各服行情并重新生成游戏中已安装的过滤器。

[从 GitHub Releases 下载 Windows 安装包](https://github.com/graydovee/poe2-realtime-filter/releases/latest)

## 安装与更新

从发布页下载 `poe2-realtime-filter-windows-x64-vX.Y.Z-setup.exe` 并运行。安装器会复用系统已有的 Microsoft Edge WebView2。如果系统缺少 WebView2，安装器会联网从微软下载并安装运行时。

客户端启动时检查更新。版本号旁出现「更新」时，点击下载，等签名校验通过后选择「安装并重启」。

## 制作第一个方案

1. 打开客户端，在「方案库」里点击「新建方案」，选择你正在玩的赛季。
2. 选择基础过滤器，或直接制作纯自定义规则方案。点击「选择已有过滤器」浏览游戏目录和方案包导入的过滤器，关闭「隐藏订阅过滤器」可查看游戏已缓存的订阅文件。也可以选择本地 `.filter`，或通过「下载过滤器」获取 NeverSink。点击「清除基础过滤器」可切回纯自定义规则。
3. 调整规则。新方案自带崇高石、混沌石、剥离石和神圣石四个价格档，它们是普通规则，区间和物品范围都可以改。这四条默认跟随基础特效，沿用基础过滤器里对应通货的字体、光柱、地图图标和音效；换一个特效预设或手动修改后，改用固定特效。未切割宝石按等级分成独立物品（技能、精魂 1–20 级，辅助 1–5 级），各等级有自己的价格，勾选对应等级即可。
4. 点击「预览」查看生成结果和安全检查，再点「保存方案」并填写方案名。回到「方案库」，点「安装到游戏」生成过滤器。进入 PoE2，在游戏设置中选中以方案名命名的过滤器。

默认安装到 Windows 文档目录下的 `My Games\Path of Exile 2`。可以在方案库检查器的「过滤器目录」里指定其他目录。两服共用过滤器目录，已有安装使用原目录。如需搬到新目录，先卸载过滤器，再重新安装。

选定基础过滤器后，未知物品、未匹配物品和被跳过的物品沿用基础规则。纯自定义方案中的未匹配物品使用游戏默认显示。

分享码引用的基础过滤器在本机缺失时，如果下载来源提供同名过滤器，可在「方案库」直接下载并绑定。

## 行情与自动刷新

选择「腾讯服 POE2」可使用 poecurrency.top 的赛季与行情。选择「国际服 POE2」可使用 poe.ninja。「方案库」显示当前服务器的方案。

- 在「方案库」选择赛季并点击「刷新行情」，可以立即获取该赛季的报价。价格条件按当前赛季的行情换算成崇高石比较，价格数据需要联网获取。
- 自动刷新默认每 2 小时检查行情和下载的基础过滤器。同服务器、同赛季的方案共用行情，同来源的方案共用发布检查与下载。已安装且开启「自动刷新」的方案会更新游戏里的过滤器。可以在「刷新设置」里调整间隔或暂停后台刷新。
- 关闭窗口后，托盘中的客户端会继续刷新。从托盘菜单退出即可停止。行情请求失败、所需文件缺失或安全检查未通过时，游戏继续使用上一次成功生成的文件。
- 在方案库检查器的「启动」设置里开启「开机启动」，登录 Windows 后客户端直接在托盘中运行，不打开窗口。双击托盘图标或选择「打开过滤器编辑器」即可打开。

## 分享、备份与管理

| 要做什么 | 在哪里操作 |
| --- | --- |
| 分享完整的方案 | 在方案详情里点「导出方案包」，把方案连同它用到的基础过滤器和音效打成一个包。在方案库点「导出方案包…」可以一次打包多个方案。接收者在「导入方案包」选择文件。作者更新了包之后，再导入一次就按 ID 更新；已是最新的方案会跳过。 |
| 只分享规则 | 在方案的「更多 → 分享码」复制。接收者在「导入分享码」粘贴并创建方案。客户端会在游戏目录按名称匹配所引用的基础过滤器，找不到时再找方案包导入的副本。需要处理的引用会显示在「方案库」里，可在编辑器里选择或清除。自定义音效按提示补齐。 |
| 获取可直接使用的过滤器 | 「更多 → 下载 ZIP」保存 ZIP，内含 `.filter` 和需要随包分发的音效。解压到游戏过滤器目录。 |
| 修改游戏里的过滤器名称 | 「更多 → 重命名」同步调整方案名和已安装的过滤器文件名。遇到重名或外部文件冲突时，客户端会提示处理。 |
| 停止使用某个过滤器 | 点击「卸载过滤器」移除游戏中的 `.filter` 并保留方案。通过「更多 → 删除」删除方案时，默认保留游戏中的文件。 |

方案、设置、音效和缓存存放在安装目录的 `data` 子目录。重装或换电脑前可以备份整个 `data` 目录。方案包带进来的基础过滤器副本也在其中（`data\base-filters\imported`），只出现在客户端的「选择已有过滤器」里。选用本地 `.filter` 作为基础过滤器时，还要备份原文件及其依赖。恢复后如果文件路径变了，在编辑器里重新选择基础过滤器。

## 本地开发

文档和界面的用词以[术语表](docs/glossary.md)为准。客户端使用 Tauri 2、Rust 和 React，编辑器与后台刷新共用 TypeScript 过滤器生成逻辑。Windows 开发环境需要 Node.js 22、Rust stable、带 C++ 工作负载的 Visual Studio Build Tools 和 WebView2。

```powershell
npm ci
rustup target add x86_64-pc-windows-msvc
npm run tauri -- dev
```

运行测试并构建本地验收安装包：

```powershell
npm test
npm run build:engine
cargo test --locked --manifest-path src-tauri/Cargo.toml --target x86_64-pc-windows-msvc
npm run tauri -- build --ci --no-sign --target x86_64-pc-windows-msvc -- --locked
```

安装包生成在 `src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/`。正式发布由 `vX.Y.Z` 标签触发，GitHub Actions 构建带更新签名的安装包，并生成指向同一个安装包的 `latest.json`。参见 [Windows 发布工作流](.github/workflows/release.yml)。
